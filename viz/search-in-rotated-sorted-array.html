Search in Rotated Sorted Array, step by step

Cut at mid and one half is always sorted. If nums[low] <= nums[mid], the left half low…mid is sorted; otherwise the right half mid…high is. In the sorted half you can tell for sure whether target is inside (it lies between its two ends). If yes, search there; if no, search the other half.

Why one half is always sorted: the array drops only once. The drop is either left of mid or right of mid, never both, so the other side has no drop.
Why test the sorted half: only there does "between its first and last value" prove target is inside. The other half might wrap around, so you can't check it directly; you just go there when the sorted half is ruled out.
Why <= in nums[low] <= nums[mid]: when low == mid (two elements left), the "left half" is just one element, which counts as sorted.
