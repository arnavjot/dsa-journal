Why look up before saving: a number can't pair with itself. In [3,2,4] with target 6, the 3 needs another 3; the map is still empty, so it isn't fooled into using the same 3 twice.

  
Why the map stores number → index: the answer is two indices, so when you find the partner you need to know where it was. seen[rem] gives exactly that.

  
About the picture: the map is drawn left to right in the order numbers were saved. A real unordered_map keeps no order; it finds a key by hashing it, which is why seen.count(rem) is O(1) on average.

  
Why one pass is enough: whichever number of the pair comes second finds the first one already saved. Try "Repeat number": the second 3 finds the first.
