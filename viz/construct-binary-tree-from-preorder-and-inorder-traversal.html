Construct Binary Tree from Preorder and Inorder, step by step

Preorder lists a root before its subtrees, so the next unused preorder value is always the root of the part being built. Inorder lists left subtree, root, right subtree, so the root's position in inorder splits the range into the left part and the right part. Build left first (that's the order preorder uses), then right.

Why the map: finding the root's position in inorder by searching would cost O(n) per node (O(n²) total). The map gives it in O(1).
Why int& preIndex: all calls consume preorder from one shared position, in exactly the order preorder lists nodes.
Why left before right: preorder is root, left, right; building in the same order keeps preIndex pointing at the right root.
Base case: an empty inorder range (start > end) means no subtree there.
