Min Stack, step by step

Every element is stored as a pair: (val, min of everything up to here). The min at each level never changes while that element sits on the stack, so getMin() just reads the top pair. When you pop, the min below is already waiting. Everything is O(1).

Why one min variable isn't enough: if you only kept the current min and then popped it, you'd have no idea what the min was before. Storing it with every element remembers the min at every level.

  
Why min(oldMin, val): the new min is either the new value or the min of everything already below it, which the top pair already knows.

  
Try "Equal mins": pushing a second 3 stores min 3 again, so popping one 3 still leaves the right min.
