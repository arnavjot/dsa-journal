Run this on every problem

Say it out loud. This is how you always have an approach, and it's exactly what the interviewer grades.

  1. Restate + clarify (1 min)Repeat the problem in your own words. Ask: input size? value ranges? sorted? duplicates? empty input? expected output on ties? Asking size is secretly asking what complexity they want.
  2. Work a tiny example by hand (1 min)4–6 elements, plus one edge case. This exposes the pattern.
  3. Name the brute force + its complexity (1 min)Always. "Brute force is every pair, O(n²); let's do better." You've banked a working answer and shown judgment.
  4. Pattern-match out loud (1–2 min)Say the trigger: "'longest substring with a condition', that's a variable sliding window."
  5. State the plan before coding (1 min)Data structures + loop shape + complexity target. Get a nod.
  6. Code it (10–15 min), narratingLeave vertical space, name variables properly (left, right, seen, count, not i2, x). Don't erase, cross out.
  7. Dry-run on your example (3–5 min)Trace every variable through the tiny example, then the edge case (empty / single / all-same). Finding your own bug scores higher than lucking into correctness.
  8. State final complexity + one extension"O(n) time, O(k) space; if the array didn't fit in memory I'd stream it in chunks." Free seniority signal.

Don't recognize the problem? Ask these in order. One almost always unlocks the pattern.

  1. Would sorting help?Two pointers, intervals, greedy, or binary search.
  2. Can I trade space for time with a hash map?Counting, seen-before, complement lookup (Two Sum shape).
  3. Best / longest / shortest contiguous thing?Sliding window (or Kadane / prefix sum).
  4. Pairs / adjacency / reachability on a grid or network?BFS / DFS. BFS if it says shortest or minimum steps.
  5. k-th / top-k / most frequent?Heap (or quickselect / bucket sort).
  6. Count the ways / min cost to reach the end, overlapping subproblems?DP: define state, recurrence, base case, order.

Still stuck? Say: "Let me start with the brute force and look for the bottleneck." Then optimize the bottleneck with the list above. Interviewers pass people who reason; they fail people who freeze or bluff.
